# تسليم ميزات مريم إلى أمل

> اكتمل الربط: يُحمّل `storage.js` ثم `app.js` بعد مكونات الواجهة، وأُزيل `landing.js`. أصبح الحفظ والحذف مع التأكيد والتصفية والترتيب متاحًا في الصفحة الحالية. البنود أدناه توثق عقد التسليم الأصلي؛ المعاينة المؤقتة المذكورة لم تعد مستخدمة. راجعي `README.md` للحالة الحالية وتعليمات التشغيل والاختبارات.

## المنجز

- نموذج إضافة وتعديل مع التحقق العربي، تاريخ محلي افتراضي، وإلغاء دون تغيير السجل.
- رسم دائري يحسب نسب التصنيفات من السجلات المعطاة، مع ألوان ثابتة ووصف مقروء لقارئات الشاشة.
- واجهة عرض قابلة لإعادة الاستخدام مع زر تعديل، وحالتي قائمة فارغة ونتائج تصفية فارغة.
- أزرار مناسبة للمس وتخطيط للشاشات الصغيرة ونموذج قابل للتمرير.

## ترتيب تحميل الملفات

`expense-form.js` ثم `expense-chart.js` ثم `expense-ui.js` ثم ملف التحكم.
حاليًا ملف التحكم هو `landing.js` لتجربة مؤقتة في الذاكرة فقط. استبدليه بـ `app.js` عند الربط؛ لا تحمليهما معًا.

## شكل السجل

```js
{ id: 'UUID', amountCents: 1235, category: 'الصحة', date: '2026-09-16', description: '' }
```

المبلغ عدد صحيح بالهللات. التصنيفات: الطعام والمشروبات، المواصلات، التسوق، الفواتير، الترفيه، الصحة، أخرى. الوصف اختياري. التاريخ YYYY-MM-DD دون تحويله إلى UTC. يتحقق النموذج من المبلغ بين 1 و100000000 هللة والوصف حتى 60 حرفًا.

## النموذج

- `CashTrackForm.openCreate()` يفتح نموذجًا جديدًا.
- `CashTrackForm.openEdit(expense)` يعبئ نسخة من البيانات، ولا يغير السجل الأصلي.
- `expense:create` و`expense:update` حدثان على `#expense-form`، يتصاعدان إلى document. السجل الجديد في `event.detail`، ويحافظ التعديل على id نفسه.
- الإلغاء والإغلاق وEscape لا يطلقون حدث حفظ.
- عند فشل الحفظ المتزامن: استدعي `event.preventDefault()` داخل المستمع؛ يبقى النموذج مفتوحًا وتظهر رسالة فشل. هذا العقد مصمم لـ localStorage المتزامن، ويحتاج تعديلًا إذا أضيف حفظ عبر الشبكة لاحقًا.

## تحديث الواجهة

```js
CashTrackUI.render(visibleExpenses, {
  filtered: filtersAreActive,
  totalCents: visibleExpenses.reduce((sum, item) => sum + item.amountCents, 0)
});
```

تعرض الدالة السجلات بالترتيب المرسل، وتحدث الإجمالي والرسم وحالة القائمة الفارغة. لا تحفظ البيانات ولا تنفذ تصفية أو حذفًا. مرري ناتج التصفية نفسه للرسم والقائمة. لعرض الرسم مستقلًا: `CashTrackChart.render(visibleExpenses, { filtered: true })`.

زر إعادة ضبط التصفية في الحالة الفارغة يطلق `expenses:reset-filters` على document؛ اربطيه بتصفير المرشحات وإعادة العرض.

## المطلوب من أمل

1. إنشاء storage.js لتحميل السجلات والتحقق منها وحفظها، والتعامل مع تعذر التخزين.
2. إنشاء app.js وربط حدثي الإضافة والتعديل بالحفظ وتحديث العرض بعد نجاحه.
3. تنفيذ الحذف مع التأكيد، والتصفية حسب التصنيف والتاريخ، وترتيب السجلات.
4. إعادة استدعاء CashTrackUI.render بعد التحميل وكل إضافة أو تعديل أو حذف أو تصفية.
5. نقل تحديث السنة من landing.js، وحذف تحميل المعاينة المؤقتة، وتحديث نصوص الموقع بعد نجاح الحفظ الفعلي.
6. اختبار بقاء البيانات بعد التحديث، والحذف، والتصفية وإعادة ضبطها وفشل التخزين.

لا توجد بيانات تجريبية جاهزة؛ البداية قائمة فارغة وإجمالي صفر. المعاينة الحالية تدعم الإضافة والتعديل والرسم فقط، وتفقد السجلات بعد تحديث الصفحة.
