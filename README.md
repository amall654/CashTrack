# CashTrack

## نبذة عن المشروع

**CashTrack** هو مشروع موقع إلكتروني بسيط يساعد المستخدم على تسجيل مصروفاته اليومية وتنظيمها حسب التصنيف، مثل الطعام والمواصلات والتسوق. يهدف الموقع إلى عرض المصروفات وحساب إجمالي الإنفاق تلقائيًا، ليتمكن المستخدم من معرفة أين تذهب أمواله ومتابعة إنفاقه بشكل أوضح.

## حالة المشروع

المشروع في مرحلة التخطيط، ويحتوي المستودع حاليًا على هذا الملف التعريفي فقط. الميزات والتقنيات وتقسيم العمل أدناه تمثل خطة مقترحة للتنفيذ، وليست وظائف جاهزة للاستخدام.

## أهداف المشروع

- تسهيل تسجيل المصروفات اليومية في مكان واحد.
- تنظيم المصروفات ضمن تصنيفات واضحة.
- تقليل الحاجة إلى حساب إجمالي الإنفاق يدويًا.
- توفير واجهة عربية بسيطة وسهلة الاستخدام على الهاتف والحاسوب.
- مساعدة المستخدم على فهم عادات الإنفاق ومتابعة ميزانيته.

## الميزات المخطط لها

- **إضافة مصروف:** إدخال المبلغ والتصنيف والتاريخ ووصف اختياري.
- **عرض المصروفات:** عرض السجلات وتفاصيلها في قائمة واضحة.
- **تعديل المصروف:** تصحيح البيانات المسجلة أو تحديثها.
- **حذف المصروف:** إزالة السجلات غير المطلوبة.
- **تصفية المصروفات:** البحث ضمن السجلات حسب التصنيف والتاريخ.
- **حساب الإجمالي:** عرض إجمالي المصروفات، وإجمالي النتائج عند تطبيق التصفية.
- **حفظ البيانات محليًا:** الاحتفاظ بالمصروفات بعد تحديث الصفحة باستخدام `localStorage` في النسخة الأولى المقترحة.
- **التحقق من المدخلات:** التأكد من أن المبلغ رقم موجب وأن الحقول المطلوبة مكتملة.

### تصنيفات مقترحة

الطعام، المواصلات، التسوق، الفواتير، الترفيه، الصحة، وأخرى.

## رحلة المستخدم

1. يفتح المستخدم الصفحة الرئيسية ويطّلع على المصروفات المسجلة وإجمالي الإنفاق.
2. يدخل بيانات مصروف جديد ويحفظه.
3. يظهر المصروف في القائمة ويتحدث الإجمالي تلقائيًا.
4. يستطيع المستخدم تعديل المصروف أو حذفه، وتصفية السجلات حسب حاجته.

## التقنيات المقترحة

| التقنية | الاستخدام |
| --- | --- |
| HTML | بناء هيكل الصفحة ونموذج إدخال المصروفات |
| CSS | تنسيق الواجهة ودعم أحجام الشاشات المختلفة واتجاه الكتابة من اليمين إلى اليسار |
| JavaScript | تنفيذ الإضافة والتعديل والحذف والتصفية وحساب الإجمالي |
| localStorage | حفظ المصروفات داخل متصفح المستخدم |
| Git وGitHub | إدارة الإصدارات وتنظيم العمل بين أعضاء الفريق |

لا تتطلب النسخة الأولى المقترحة تسجيل دخول أو خادمًا أو قاعدة بيانات. البيانات المحفوظة في `localStorage` مرتبطة بالمتصفح والجهاز، ولا تتزامن تلقائيًا بين الأجهزة، وقد تُفقد عند مسح بيانات الموقع. يُقترح استخدام عملة واحدة لجميع المصروفات في هذه النسخة حتى يكون الإجمالي واضحًا.

## بيانات المصروف

| الحقل | الوصف |
| --- | --- |
| `id` | معرّف فريد لكل مصروف |
| `amount` | مبلغ المصروف، ويجب أن يكون أكبر من صفر |
| `category` | تصنيف المصروف |
| `date` | تاريخ المصروف بصيغة `YYYY-MM-DD` |
| `description` | وصف اختياري يوضح سبب المصروف |

## هيكل الملفات المقترح

الملفات التالية ستُضاف عند بدء التنفيذ:

```text
CashTrack/
├── README.md
├── index.html
├── css/
│   └── style.css
└── js/
    ├── app.js
    ├── expense-form.js
    ├── expense-list.js
    └── storage.js
```

- `app.js`: تهيئة التطبيق وربط مكوناته وتحديث العرض بعد تغيير البيانات.
- `expense-form.js`: إدارة نموذج إضافة المصروف وتعديله والتحقق من المدخلات.
- `expense-list.js`: عرض المصروفات والتصفية والحذف وحساب الإجمالي.
- `storage.js`: قراءة البيانات من التخزين المحلي وحفظها.

## تقسيم العمل المقترح

| المسؤولة | المهام | الفرع |
| --- | --- | --- |
| أمل | تصميم الواجهة الأساسية، نموذج إضافة المصروف وتعديله، والتحقق من المدخلات | `Amal` |
| مريم | عرض المصروفات وحذفها وتصفيتها، حساب الإجمالي، وحفظ البيانات واسترجاعها | `Mariam` |
| معًا | الاتفاق على شكل البيانات، ربط المكونات، مراجعة التغييرات، اختبار الموقع، وتحديث التوثيق | الدمج في `main` بعد المراجعة |

يُفضّل الاتفاق على الدوال المشتركة وشكل بيانات المصروف قبل التنفيذ، وتنسيق التعديلات على الملفات المشتركة لتقليل تعارضات الدمج.

## مراحل التنفيذ

- [ ] اعتماد التصميم وشكل البيانات وتوزيع المهام.
- [ ] إنشاء هيكل الصفحة وتنسيق الواجهة العربية.
- [ ] تنفيذ إضافة المصروفات وعرضها وحفظها محليًا.
- [ ] إضافة التعديل والحذف والتصفية وحساب الإجمالي.
- [ ] ربط المكونات واختبار الاستخدام على الهاتف والحاسوب.
- [ ] مراجعة المشروع وتحديث تعليمات التشغيل ودمج النسخة المستقرة.

## التشغيل

لا توجد نسخة قابلة للتشغيل حاليًا لأن ملفات التطبيق لم تُنشأ بعد. ستُضاف خطوات التشغيل عند تنفيذ الواجهة واعتماد التقنيات النهائية.

## التحقق من عمل المشروع

عند اكتمال التنفيذ، ينبغي التأكد من الحالات التالية:

- إضافة مصروف صحيح وظهوره في القائمة وتحديث الإجمالي.
- رفض المبالغ الفارغة أو غير الرقمية أو غير الموجبة.
- تعديل المصروف وانعكاس التغيير على القائمة والإجمالي.
- حذف المصروف وتحديث البيانات المحفوظة.
- تصفية السجلات وعرض إجمالي النتائج المطابقة.
- بقاء البيانات بعد تحديث الصفحة.
- عرض حالة واضحة عندما لا توجد مصروفات أو نتائج للتصفية.
- سهولة استخدام الواجهة العربية على مختلف أحجام الشاشات.

## أفكار للتطوير مستقبلًا

- عرض رسوم بيانية لتوزيع الإنفاق حسب التصنيف.
- تحديد ميزانية شهرية والتنبيه عند الاقتراب منها.
- تصدير المصروفات واستيرادها لعمل نسخ احتياطية.
- إضافة حسابات مستخدمين وقاعدة بيانات لمزامنة المصروفات بين الأجهزة.
